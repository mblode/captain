## Decisions for the reviewer

- Lockfile: run `pnpm import` against `package-lock.json` (not a fresh `pnpm install`) so every resolved version carries over unchanged, then delete `package-lock.json`.
- `packageManager` pinned to `pnpm@12.8.1` (current npm-registry latest), matching the pattern already live in `react-vello` (single-package repo, same toolchain: oxlint/oxfmt/ultracite, lefthook, changesets).
- CI and release workflows switch to `pnpm/action-setup@v4` + `cache: pnpm`, dropping the npm-only "Upgrade npm for OIDC trusted publishing" step — `react-vello`'s release workflow publishes with provenance via plain `pnpm install --frozen-lockfile` + `pnpm run release`, no npm-version pin needed.
- `lefthook.yml`'s oxfmt job drops its `package-lock.json` exclude: that job's glob is `*.{json,jsonc,css}`, and `pnpm-lock.yaml` doesn't match a JSON glob, so the empty-set failure the exclude guarded against can no longer happen.
- No Dockerfile or `vercel.json` exist in this repo (checked), so those two file classes from the task have nothing to change here. `dependabot.yml`'s `package-ecosystem: npm` is left as-is — GitHub's npm ecosystem covers `pnpm-lock.yaml` too.
